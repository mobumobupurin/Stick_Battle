# STICK WORLD beta
Pages entry: /Stick_Battle/world/. Local practice ships with 1F bank + daily bonus, 2F link to original HUB, 3F medal drop (illustrated random payout, not physics), 4F roulette. Keyboard/touch walking, floor movement, name, cash/bank/record and position stored on the device. Online profile/presence/shared roulette/bank/admin are implemented as callable Function source, **not deployed by GitHub Pages**. No real money, purchase, redemption or external prizes. Existing HUB casino games remain unchanged; this is an additional entrance, not a migration. Online PvP, full-size medal machines and poker/blackjack/baccarat migration are future work.
 
## Firebase operator deployment
Existing project: stick-fight-bac45. Do not use the existing public Realtime Database for balances. This beta uses a separate Firestore namespace accessed only by Admin SDK. The Firebase project owner must:
1. Review current Firestore rules. Enable Firestore and email/password Auth. Apply the deny rules only if Firestore is unused; otherwise merge rules so stickWorldProfiles, stickWorldRounds and stickWorldAudit cannot be accessed directly, including via broader wildcard rules. Test denied client reads/writes. Existing Realtime Database is NOT changed.
2. Firebase Cloud Functions deployment requires billing/Blaze and authorized Firebase CLI. Run `firebase login`, `firebase use stick-fight-bac45`, `cd functions && npm install && cd ..`, then `firebase deploy --only functions:worldAction --project stick-fight-bac45`. Deploy Firestore rules separately, only after the review above. Add Pages origin to Firebase Auth authorized domains if needed.
3. Register an operator account and note its UID. Using Application Default Credentials with explicit project, run `GOOGLE_CLOUD_PROJECT=stick-fight-bac45 node functions/grant-admin.cjs <UID>`. Sign out and back in to refresh custom claims. Never expose service account credentials. Admin can mint, transfer own balance, burn and audit. The browser never grants roles. 
4. Test two accounts online: same round, closed bets rejected, settlement replay rejected, daily claim once, bank conservation, restart persistence, admin permission denied for ordinary users. Test latency and multi-device reconnect. Until successful, online is **not verified** and only practice is advertised. After successful backend verification, set window.STICK_WORLD_ONLINE=true in world/config.js and publish the change. 
5. Production: add App Check and quotas/rate limits, retention policy for receipts, wallet/bank cap edge-case handling, monitoring, stable backups, and consent/privacy notice. Online presence is polled every 4 seconds, not continuous real-time. The beta stores email in Firebase Auth, name/position/virtual balances in Firestore; no cash transactions.
