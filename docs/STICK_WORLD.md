## Console setup (free Spark plan)
1. Firebase project stick-fight-bac45: Authentication → Sign-in method → Enable Anonymous and Google (email/password is not required). For Google select a project support email, then add mobumobupurin.github.io under Authentication → Settings → Authorized domains.
2. Realtime Database → Rules: back up existing rules, paste the **entire database.rules.json** included in this repo (rooms and kumite_rankings_v1 preserved as supplied 2026-11-19); publish. No Cloud Functions or Firestore needed. Do not deploy the old firebase.json/Firestore configuration.
3. Enter a nickname in STICK WORLD and click online play, then copy your UID (Authentication → Users). Realtime Database → Data: under stick_world create admins, inside it add a child with your UID as key and Boolean true as value. Only project console operators can grant roles; browser cannot write the admins path. Return to practice and enter online again (do not sign out of Firebase).
4. Test two accounts: separate private profiles, bank conservation, daily bonus once per Japan day, save/relogin, presence, shared round result and settlement, admin operations (normal users denied). Rules must be tested in the Firebase emulator or console before trusting use. Existing public room permissions are unchanged.

Online uses Auth + RTDB, server-clock rules, profile transactions, a protected admin list and shared result creation after closing. Results are generated by a participating browser, not a trusted server; clients can choose draw outcomes or falsify bounded medal results. Not suitable for monetary value or adversarial competitive play. Practice balances are separate. Admin transfer is atomic across the profiles tree; admin log is a separate append and can fail. Presence is polled, stale entries hidden; round/history data grows, monitor Spark limits. New game modes and physical coin-pusher remain incomplete. Old Functions source retained only for a future paid trusted backend; not deployed or used.

Anonymous authentication persists the UID within the same browser profile. Returning to practice keeps that identity. Clearing site data, signing out externally, using another browser/device or losing the browser profile can make the original account inaccessible. Existing persisted email accounts are reused without changing their UID; there is no new email sign-in form. No account recovery or cross-device migration in this version.

Google login is optional. Anonymous → Google calls linkWithPopup, preserving the Firebase UID and therefore the same RTDB profile and administrator membership. If the Google credential belongs to another existing UID, linking fails without merging or deleting data. A fresh browser can use Google sign-in to resume the linked UID. A linked Google user can explicitly sign out and select a different Google account later. Google authentication processes Google account identity data in Firebase Auth; game profiles do not store email. Browser popup support is required; redirect fallback is not implemented. Test fresh Google login, linking with preserved UID/balance, duplicate credential, administrator preservation, and cross-device restore before relying on this feature.

Admin picker: loads registered profiles only for an authenticated administrator, supports nickname and UID search, shows balances, includes offline accounts and self, sends exact UID, and does not ask for a reason. Existing adminLog rules still require a reason field; the application supplies a fixed label automatically. No Firebase rules changes required. A retained value listener primes the RTDB transaction cache before running mutations; live verification of the reported missing-profile error is still required.

Resort lobby refresh: decorative SVG floor art, distinctive four-floor themes, responsive map-first mobile layout, separate wallet/bank HUD, nearby interaction cue, avatar sprites and same-floor player names. All saved coordinates, OAuth identities, profile fields and Firebase rules are unchanged. Decorations do not block movement; this is a visual and navigation improvement, not a new physics or game mode release.

Royal Casino roulette table (UI refresh): modal dialogs for all facility panels, an SVG European wheel with spin/ball animation that lands on the actual draw, a felt betting layout (numbers 0–36, red/black/even/odd) with stackable chips (10/50/100/500/1K, one bet per spin as before), result history (kept in the browser), a round countdown bar for online play and automatic settlement once a round's result is available (also attempted from the background poll when the table is closed). Presentation only: bet validation, draws, payouts and Firebase rules are unchanged. The wallet display is held during the spin so the outcome is not revealed early. Mobile uses a vertical table and a sticky chip bar.


## STICK CASINO（2026-11 リニューアル）
STICK WORLD を独立ゲーム「STICK CASINO」に改名。本編メインメニューの「06 スティックカジノ」から `/world/` を開く（URLは互換のため据え置き）。ゲームHUB内のリンクは削除。

- フロア：1F エントランス（キャッシャー・ボーナス・出口）／2F スロットホール（スロット・メダル落とし）／3F カードルーム（ブラックジャック）／4F ルーレットサロン（共通ルーレット）。保存済みのフロアIDと座標はそのまま。
- ページ上部の「今夜のテーブル」から、歩かずに各ゲームを直接開ける。
- **スロット**（`world/slot.js`）：3リール・6絵柄、3つそろい（×6〜×300）と左2つそろい（×2）。ベット 10/20/50/100。理論還元率 約96%（`slotRtp()`）。抽選は core.js の `slot` アクション。
- **ブラックジャック**（`world/blackjack.js`）：6デッキ、ディーラーは17以上でスタンド、BJは1.5倍、最初の2枚でダブル可。ベット 10〜1,000。手札はブラウザ内で配り、結果だけを core.js の `blackjack` アクションで精算する。途中で閉じた手は精算されない。
- **オンライン保存**：`database.rules.json` の profiles 書き込みルールに「カジノ1プレイ分」の枝を追加（plays +1、wins 同じか +1、ルーレット未精算なし、所持金の増加 30,000 以下・減少 2,000 以下）。**Firebaseコンソールで Realtime Database → ルール にこのファイル全体を貼り直して公開すること。** 貼り直すまで、オンラインでのスロット・ブラックジャックは保存エラーになる（練習版は動く）。
- 抽選と結果はブラウザ側で行うため、不正対策には限界がある（従来どおり）。架空チップ専用。


## STICK ROYALE（2026-11-20 リニューアル）
名前を「STICK ROYALE — GAMING CASINO」に変更。本物のカジノの電子ゲーム機（EGM）をイメージした筐体UIに統一：上部のネオン看板、CREDIT / BET / WIN の電光メーター、光るボタン、Web Audio で合成した効果音（♪ボタンで消音、ブラウザごとに記憶）。

- **STICK FORTUNE**（`world/slot.js`）：5リール×3段・10ライン。WILD（BONUS以外の代わり）、BONUS 3個以上でフリーゲーム8/10/15回（当たり2倍）。BONUSが2つ見えると残りのリールが光ってゆっくり止まる演出、当たりラインの表示、15倍以上で BIG/SUPER/MEGA WIN とコインの演出、AUTO（25回）。理論還元率 約94%、1回の払い出しはベットの300倍まで。抽選はすべて core.js の `slot` で行い、フリーゲームも同じ1回の精算に含む。
- **JACKS OR BETTER**（`world/videopoker.js`）：9/6ジャックス・オア・ベター。ベット 10/20/30。HOLDしてDRAW。最終手札を core.js の `videopoker` が役判定して精算（カードの重複などは拒否）。
- **BACCARAT**（`world/baccarat.js`）：PLAYER 1:1 ／ BANKER 0.95:1 ／ TIE 8:1（TIEのときPLAYER・BANKERのベットは返却）。3枚目ルールまで core.js の `baccarat` が配って判定。ビーズロード（履歴）はブラウザに保存。
- **BLACKJACK**・**ROULETTE**・**MEDAL DROP** は従来どおり（BJは筐体デザインに変更）。
- フロア：2F スロット＆ポーカー／3F テーブルゲーム（BJ・バカラ）。
- オンライン保存は既存の「カジノ1プレイ分」ルール（増加30,000以下・減少2,000以下）の範囲に収まるため、**Firebaseルールの変更は不要**。
- ゲームHUBからブラックジャック・ポーカー・バカラを外した（カジノ系はすべて STICK ROYALE に集約）。

### メダルコーナー（2026-11-20）
ゲームセンターのメダルコーナー風のエリアを追加。GAMES は「マシン」「メダルコーナー」「テーブル」の3エリア。フロアは 2F スロット＆ポーカー／3F メダルコーナー／4F テーブルゲーム（BJ・バカラ・ルーレット）。
- **COIN PUSHER**（`world/pushersim.js` + `world/medalpusher.js`）：1枚 = 1 SC。タップ位置（◀▶/DROP、キーボード←→・スペース）にメダルを落とすと、前後に動くプッシャーがフィールドのメダルを押し出す。手前から落ちたら払い出し、左右の端（OUT）に落ちたら没収。投入のたび 3.5% で CHANCE → 3桁抽選（333 +5／555 +15／777 +40／★★★ +150 枚をフィールドに追加）。フィールドはブラウザごとに保存。投入・払い出しは手元で数え、2.5秒止まる・投入200枚・払い出し2000枚・「精算」ボタン・台を閉じたときに `pusher` 操作（1回あたり投入 ≤300・払い出し ≤3000）でまとめて保存する。ヘッドレス計算で還元率はおよそ 90〜95%。
- **LUCKY WHEEL**（`world/luckywheel.js`）：48マス均等のホイール（0×28・×1×9・×2×5・×3×3・×5×1・BONUS×2）。BONUS で12マスのボーナスホイール（1マスが JACKPOT ×50）。結果は `wheel` 操作で決まり、還元率 95.5%。
- **MEDAL DROP** はメダルコーナーへ移動。
- どれも既存のカジノ用ルール（1回の保存で plays +1、増加 ≤30000・減少 ≤2000）の範囲に収まるため、Firebase ルールの変更は不要。
